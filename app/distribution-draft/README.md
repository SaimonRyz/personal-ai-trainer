# Персональный ИИ-тренер — редакция для распространения

> **Экспериментальная альфа.** Установка по инструкции и MCP подтверждены владельцем. Известные ограничения — в [KNOWN_ISSUES.md](../../KNOWN_ISSUES.md). Публикация разрешается отдельно.

ИИ-тренер — локальное приложение для **одного пользователя на одной установке**. Чат Codex обращается к локальному MCP-процессу; тот использует контролируемый Python API; данные хранятся в PostgreSQL внутри Docker Compose. API и MCP доступны только через `127.0.0.1`, порт PostgreSQL наружу не публикуется. Каждый пользователь получает отдельную базу и создаёт собственные секреты на своём компьютере. Репозиторий не содержит общей пользовательской базы, ключей или аккаунта автора.

## Что должно входить в будущую поставку

- Исходный код Python-сервиса, MCP, миграции, lock-файл, Compose-файл, шаблон `.env.example`, навыки Codex и скрипты проверки/запуска.
- [Инструкция для агента установки](INSTALL_AGENT.md), доступная непосредственно после получения репозитория.
- Проверяемый способ получить **точный** dependency image для API и PostgreSQL image на поддерживаемой платформе: воспроизводимая сборка из закреплённых входов либо опубликованные артефакты с проверяемыми digest. Локальный `image_id` автора без источника получения недостаточен.
- Манифест поставки с версиями, платформой, источниками, размерами и SHA-256 всех обязательных файлов, а также проверенный сценарий установки на чистом компьютере.

Владелец подтвердил развёртывание для Mac с Apple Silicon. Поддержка Intel Mac, Windows и Linux **не проверена**; агент не должен предполагать её по сходству команд.

## Предварительное требование: Codex

Пользователь **самостоятельно устанавливает и настраивает Codex до открытия проекта**. Codex — обязательный интерфейс общения с тренером, но его установка, обновление, вход в учётную запись и изменение основного профиля **не входят** в процедуру агента установки ИИ-тренера. Агент проверяет наличие и доступность Codex; если его нет, сообщает `NOT READY` и указывает на это предварительное требование, не пытаясь установить Codex сам. Установку Docker Desktop, `uv`, Python и компонентов приложения агент выполняет только в отдельно согласованных границах.

Точные входы, [рецепт сборки](BUILD_RECIPE.md), статическая проверка и текущие пробелы описаны в [обзоре образов и зависимостей](DEPENDENCIES_AND_IMAGES.md). Успешная установка подтверждена владельцем; каждый новый компьютер проходит собственный preflight.

## Как должен выглядеть первый запуск

1. Пользователь получает проверенный выпуск и открывает его в Codex.
2. На просьбу «установи и запусти тренера» агент читает `AGENTS.md` и [INSTALL_AGENT.md](INSTALL_AGENT.md), затем одним проходом проверяет ОС, платформу, наличие Codex, Docker Desktop/Engine/Compose, `uv`, Python, целостность исходников, образы, зависимости, локальные порты и уже существующие ресурсы.
3. Агент показывает единый план недостающих установок и постоянных изменений. Системный пароль, лицензии и разрешения ОС остаются действиями пользователя. Без одобрения агент ничего не скачивает, не устанавливает и не создаёт постоянную базу.
4. После разрешения агент получает только проверенные артефакты, создаёт локальные секреты и отдельный volume, собирает/запускает приложение штатными средствами и проверяет API, MCP и обнаружение инструментов в **этом** чате. Неисправность любого обязательного шага даёт `NOT READY`, а не видимость успеха.
5. Последующие короткие команды «запусти тренера» используют уже разрешённую неизменившуюся установку без повторных запросов. Новый компьютер, база, образ или разрушительное действие требуют нового решения пользователя.

В проекте нет серверного аккаунта пользователя и облачной синхронизации. Наличие учётной записи Codex и возможные расходы на ИИ относятся к выбранному пользователем сервису, а не к локальной базе. Ключи ИИ-провайдера не вносятся в Git и не копируются из профиля автора.
