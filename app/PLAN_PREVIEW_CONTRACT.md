# Предпросмотр плана: контракт отображения

`render_preview(detail_level="full")` для черновика плана возвращает единственный текст,
который можно показать для подтверждения. Сервер связывает его с точной редакцией,
данными и зависимостями. `detail_level="details"` раскрывает ту же редакцию,
но не может быть отмечен как показанный для подтверждения.

## Сведения в основном тексте

| Данные черновика | Основное представление |
| --- | --- |
| Название, дата, время, цель, связь с программой | Заголовок и короткие строки перед структурой. Дата плана не означает факт выполнения. |
| Временное место, добавленный и исключённый инвентарь | Показывать каждое заданное изменение; пустой блок не печатать. |
| Блоки и упражнения | Порядок `position`; для круга — порядок `circuit_position`, объявленные круги и фактическое участие каждого упражнения. |
| Подходы | Группировать лишь подряд идущие подходы с одинаковыми видимыми параметрами. Для кругового блока показывать число подходов **в каждом круге**, даже когда параметры одинаковы. Разминку, отличающийся вес, сторону, отдых, темп, паузу, RPE и RIR сохранять различимыми. |
| Левая и правая стороны | «На каждую сторону» только для соседней пары в одном круге с одинаковыми параметрами. Иначе каждая сторона названа отдельно. `both` означает лишь «обе стороны»: распределение результата по сторонам не задано. |
| Повторения, время, расстояние, диапазон | Число и русская единица; неизвестное значение не заменять нулём. |
| Нагрузка | Общая внешняя масса и масса одного предмета различаются; оба сохранённых обозначения массы предмета (`per_item_mass` и `mass_per_item`) показываются одинаково. Указанное количество предметов видно даже при неизвестной массе; выбранный инвентарь и направление ленты остаются видимыми. Если компонент нагрузки не задан, прямо сказано «нагрузка не указана»; неоднозначный смысл массы не подтверждается. |
| Комментарии | Текст показан полностью. Общий комментарий отдельно назван примечанием: упомянутое только там упражнение не становится структурным пунктом плана. |
| Рекомендации | Решение, короткое и уникальное развёрнутое объяснение, допущения, альтернативы, учитываемые факты, существенная неопределённость и условие пересмотра. Недостаточную научную опору назвать прямо. |
| Научный вывод | Его формулировка и ограничения остаются в основном тексте; названия источников раскрываются в деталях. |

## Подробности и служебные данные

В `details` видны отдельные подходы и справочные требования к оборудованию,
а также основания рекомендаций и названия научных источников. Запрос подробностей
ничего не записывает, не меняет редакцию и не заменяет основной текст подтверждения.
Научный вывод и его ограничения добавляются до заключительной строки: если
черновик неполон, текст заканчивается требованием исправить его, без приглашения
подтвердить план.

Служебные идентификаторы, digest, снимки зависимостей, внутренние коды и ключи
свободных структур не печатаются в основном тексте. Они остаются в данных операции.
Если новое поле появится в контракте запроса, тест состава полей должен потребовать
явного решения о его отображении.

Если упомянутого в разговоре упражнения нет ни в структурированном плане, ни в
комментарии, сервер не может узнать о его пропуске. Тренер обязан сверить
предложение с обсуждением до создания черновика; текст предпросмотра не должен
выдумывать отсутствующее обсуждение.

Для нового кругового блока и суперсета число кругов и `round_no` каждого подхода
обязательны; допускается не более **100 кругов** в блоке. В каждом объявленном
круге нужен хотя бы один подход. При ошибке
создание черновика возвращает адресные `field_errors`. Старый черновик с пропуском
остаётся доступен для просмотра: текст называет проблемные блоки и круги, а
`complete=false` запрещает использовать его для подтверждения.
Превышение предела проверяется до обхода кругов; последовательные пустые круги
показываются диапазоном, а общий список ошибок ограничен 20 пунктами и сообщением
о необходимости повторной проверки после исправления.

Для допущений и альтернатив поддерживаются осмысленные ключи, в том числе
`rest_seconds`, `duration_minutes` и `spotter_available`. Свободное условие
передаётся как `{"description": "понятный текст"}`. Новый неизвестный ключ или
неподходящий тип получает адресную ошибку при создании. В старом черновике
неизвестный ключ и значение остаются видимыми, но такой предпросмотр получает
`complete=false`, пока рекомендацию не исправят в новом черновике.
