# Пакетное добавление знакомых упражнений

Статус: локальная установка обновлена; API и MCP готовы, изолированные синтетические проверки прошли. Пользовательская проверка нового сценария в чате тренера ещё не выполнена. Владелец выбрал один краткий итог и одно подтверждение на весь список. Это не разрешение записывать конкретные упражнения без показа этого итога и отдельного подтверждения.

## Пользовательский контракт

1. Пользователь перечисляет знакомые упражнения одним сообщением. Сам список выражает намерение подготовить изменения; до подтверждения он не записывается как факт профиля.
2. Агент ищет точные совпадения в каталоге, различает варианты упражнений и готовит недостающие карточки. При неоднозначности названия, измерения, оборудования или другой значимой характеристики спрашивает пользователя, не выбирая значение сам.
3. Сервер создаёт один пакетный черновик. Его `canonical_text` кратко перечисляет каждый исходный пункт и результат: найденная карточка, создаваемая карточка, отметка «знакомо» или причина исключения. Новые группы мышц и другие побочные изменения названы явно. Полная карточка доступна отдельным чтением по запросу.
4. Пользователь видит весь точный `canonical_text` один раз и даёт одно явное подтверждение пакета. Одно подтверждение не применяется к набору отдельных предпросмотров CMD-22.
5. После подтверждения сервер в одной транзакции создаёт необходимые карточки и группы, добавляет отметки знакомости и возвращает точные ссылки на записанные редакции. Агент читает результат обратно через API/MCP.
6. Знакомство не означает выполнения упражнения, владения техникой или пригодности упражнения сейчас.

## Данные и серверные проверки

- Вход пакета содержит порядок и исходное название каждого пункта, а также ровно один результат сопоставления: точную текущую ссылку на существующую карточку или полную новую карточку. Неразобранные пункты перечисляются отдельно и не записываются. Пустой пакет изменений отклоняется.
- Сервер проверяет допустимость каждой новой карточки, точность текущих ссылок, отсутствие дубликатов по нормализованному названию, статус и пригодность карточок для планирования. Группы мышц с одинаковыми нормализованными названиями создаются один раз на пакет.
- Пакет хранит точные зависимости от текущей редакции профиля, найденных карточек, каталожных правил и занятости названий. Перед записью они повторно проверяются. Изменение состава списка или зависимостей делает старый предпросмотр непригодным для подтверждения.
- Хеш предпросмотра связывает ревизию пакета, полные типизированные данные, `canonical_text`, зависимости и вид подтверждения. Служебные ID и digest не печатаются в пользовательском тексте.
- Подтверждение идемпотентно и транзакционно: при любой ошибке не создаются ни часть карточек, ни часть отметок. Повтор той же команды возвращает прежний результат.
- Для уже существующего профиля новая редакция профиля сохраняет прежние поля и уже известные упражнения, добавляя выбранные без дублей. Старые редакции остаются неизменными.
- Если профиля ещё нет, его создают через отдельный подтверждаемый onboarding-пакет. Сразу после этого весь список упражнений проходит одним пакетом и одним подтверждением. Нельзя записать знакомость в отсутствующий профиль; подтверждение профиля остаётся самостоятельным решением.

## Граница изменений

Используются новый пакетный API/MCP-контракт и существующие таблицы черновиков и редакций профиля. Миграция 0023 добавляет отдельный тип пакетного черновика `familiar_exercise_batch`; одна атомарная транзакция подтверждения создаёт карточки и новую редакцию профиля. Миграция 0024 добавляет тип оборудования `parallel_bars` для карточек упражнений и инвентаря.

## Проверка перед рабочим обновлением

- Адресные unit/contract/MCP-тесты для списка, краткого текста, устаревания, повторов и ошибок полей.
- Интеграционная проверка на отдельной синтетической БД: существующие и новые карточки в одном пакете, общая новая группа мышц, существующий профиль после первого знакомства, повтор команды, устаревшая зависимость и сбой перед commit.
- После согласованного обновления действующей установки — API/MCP readiness без записи личных данных. Рабочие упражнения добавляются только после отдельного пользовательского подтверждения конкретного пакетного предпросмотра.
