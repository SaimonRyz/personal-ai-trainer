# Краткая архитектура

```text
Компьютер пользователя
  Codex: чат из trainer-workspace/
    → HTTP MCP, 127.0.0.1:8768/mcp
  MCP: отдельный Python-процесс на хосте, НЕ контейнер
    → HTTP/JSON API, 127.0.0.1:8767
  Docker Compose
    API: Python/FastAPI
      → внутренняя сеть → PostgreSQL
    PostgreSQL: постоянный Docker volume, без порта на хосте
```

Это схема рабочего release/alpha-профиля. `app/compose.yaml` использует проверенные локальные image ID из настроек установки; API публикуется как `127.0.0.1:8767:8765`. Штатный lifecycle проверяет конфигурацию и управляет запуском. Не запускайте Compose как замену `trainer start`.

MCP переводит типизированные инструменты в API-запросы, не выполняет произвольный SQL. API отвечает за валидацию, транзакции, подтверждения и историю; PostgreSQL хранит данные. Skill управляет диалогом, но не является механизмом безопасности. План и фактическая тренировка разделены; запись проходит черновик, предпросмотр, подтверждение и проверку результата.

`app/src/trainer/` содержит прикладной, предметный, инфраструктурный и HTTP-слои; `app/mcp/` — MCP; `app/migrations/` — миграции. `trainer-workspace/` — отдельная область повседневного общения, а не административная консоль.

Сервисы доступны только локально. Это не изоляция от всех процессов пользователя: локальные процессы считаются доверенными. Данные, переданные в диалоге Codex, обрабатываются выбранным ИИ-сервисом; локальная БД не делает сам ИИ офлайн. Учётные записи Codex не поставляются с приложением.
